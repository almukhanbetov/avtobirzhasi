## 10. Необходимые изменения GitHub Actions

**Функционально — ни одного.** Существующий `deploy.yml` уже:
- Прогоняет ровно те же quality gates, что использовались локально весь этот сеанс (`go build`/
  `go vet`/`go test -p 1 ./...` с реальными миграциями на эфемерном CI Postgres; `npm run test`/

- Применяет миграции идемпотентно перед переключением контейнеров.
- Не удаляет тома, не форсирует пересоздание БД.
- Уже устанавливает и проверяет ежедневный бэкап при каждом деплое.

**Единственное, что нужно (не изменение workflow, а отдельный шаг вне него):** способ разово
прогнать `import-locations` против production — этот шаг **намеренно не входит** в `deploy.yml` и
не должен запускаться автоматически при каждом push (справочник загружается один раз, повторный

## 12. План отката

- **Откат приложения (образов):** `docker compose -f docker-compose.prod.yml pull
  <backend_или_frontend>@<сохранённый_digest>` (или ручное указание тега предыдущей версии, если
  используется не только `:latest`) → `docker compose up -d` для отдельного сервиса. Быстро,
  безопасно, не трогает данные.
- **Критически важно (прямо указано заданием и подтверждено чтением кода):** откат Docker-образа
  **не откатывает уже применённые миграции PostgreSQL** — `goose` необратимо изменяет схему
  вперёд при каждом успешном деплое. Если откат образа нужен из-за проблемы, вызванной именно
  миграцией 00014 (новые таблицы/колонки), одного отката образа недостаточно:
  1. Откатить образ backend (см. выше) — старый код не знает о новых колонках и просто их не
     использует (они `nullable`, ничего не ломает у старого кода).
  2. Если требуется откатить и саму схему — `goose down` вручную, по одной миграции, **только
     после** внепланового бэкапа перед этим действием, и только если 00014 действительно оказалась
     причиной проблемы (маловероятно — она чисто аддитивная).
  3. Если сами данные повреждены — восстановление из бэкапа (`scripts/restore-db.sh`) во временную
     БД для проверки, и только затем — осознанное решение о переключении production на неё.
- Тома (`avtobirzhasi_pgdata`, `avtobirzhasi_uploads`) при откате не трогаются в любом случае.
